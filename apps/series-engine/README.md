# Сборка языковых версий сериала

Исходная раскадровка хранится один раз. Движок распознаёт надписи на отмеченных кадрах, накладывает перевод поверх оригинала и экспортирует отдельные копии. Для монтажа берёт фактический тайминг озвучки каждого языка.

## Интерфейс в браузере

Для запуска нужны Python 3.10 или новее, FFmpeg и FFprobe в PATH. Для OCR и стандартного шрифта надписей используется Windows. FFmpeg должен поддерживать `libx264` и `drawtext`.

В Windows дважды щёлкните `series-engine/start-ui.cmd`. Скрипт запустит сервер и откроет интерфейс в браузере. Можно запустить сервер вручную из корня проекта в PowerShell.

```powershell
python series-engine/server.py
```

Если движок хранится отдельно от материалов сериала, укажите существующую рабочую папку.

```powershell
python apps/series-engine/server.py --workspace "D:\VideoProjects" --open-browser
```

Откройте [интерфейс сборки](http://127.0.0.1:8765/) и оставьте окно терминала открытым. Если порт занят, запустите сервер с `--port 8766` и откройте адрес с этим портом. Для остановки нажмите `Ctrl+C`. Если идёт сборка, сервер дождётся её окончания.

1. Если найден один проект, интерфейс откроет его автоматически. При нескольких проектах выберите нужный в списке «Найденные проекты». Если проекта нет в списке, укажите папку с `series.json` внутри рабочего каталога, например `output/seventh-car`, и нажмите «Открыть».
2. Выберите «Видео для YouTube» или «Отдельные видео» и отметьте языки с готовой озвучкой. Для YouTube выберите «Основной язык видео». Остальные отмеченные языки экспортируются отдельными WAV. В режиме отдельных версий каждый выбранный язык получает свой MP4.
3. Выберите 360p для теста или 1080p для финала. Нажмите «Проверить входные файлы», затем «Собрать видео». Следите за журналом в разделе «Ход сборки». Ссылки появятся в разделе «Готовые файлы».

Если движок сообщает об отсутствии кеша OCR, раскройте «Распознавание надписей» в разделе «Экспорт», нажмите «Распознать надписи» и повторите проверку.

В разделе «Экспорт» основные кнопки стоят перед дополнительными настройками. В «Материалах и проверках» находятся раскадровка, библиотека, диагностика, сравнение сборок и профиль качества. Очередь и готовые файлы видны справа на широком экране.

### Повтор сборки и история

Повторное использование готовых этапов включено по умолчанию. После сбоя устраните указанную причину и нажмите «Повторить с кэшем» у выбранного задания. Через API можно повторить `retry_payload` из завершившегося с ошибкой задания. Передайте `resume: false` в `POST /api/jobs` или `--no-resume` в CLI, чтобы пересобрать аудио и итоговые файлы. Проверка с `dry_run: true` не создаёт снимок.

Успешная сборка сохраняет снимок в `.build-history/` внутри проекта. Снимок содержит текст, тайминг и контрольные суммы, поэтому храните папку как часть рабочих материалов проекта. История не хранит копии MP4, WAV или исходных изображений. Для дубля сравнение показывает входной тайминг речевых блоков, а контрольная сумма WAV отражает результат синхронизации.

### Профиль качества

По умолчанию кадр длится от 1 до 9 секунд. На кадрах от 5 секунд автоматический монтаж меняет крупность резкими склейками с интервалом 2–3 секунды. Профиль позволяет изменить эти пределы с точностью до одного кадра при 25 кадрах в секунду. Ручная крупность и ручная склейка задаются отдельно для кадра.

Язык надписей исходных иллюстраций по умолчанию английский (`en`). Он задаёт источник для локализации и может отличаться от языка озвучки мастера. Профиль не меняет текст в исходных изображениях. Режим YouTube использует общие исходные изображения с дорожками разных языков.

## API для агентов

Для операций с проектом используйте API приложения. Сначала запросите данные проекта, затем отправьте задачу с `dry_run: true` и дождитесь результата. При ошибке сверьте журнал с входными файлами. Исправьте причину в проекте или в движке, обновите инструкцию, если изменилось поведение, и повторите проверку через тот же API. После успешной проверки отправьте запрос на сборку.

API доступен через тот же локальный сервер. Запросы и ответы используют JSON. Указывайте путь к проекту относительно рабочего каталога, через `/`. Одновременно выполняется одна задача. При остановке сервера история задач пропадает, а готовые файлы остаются на диске.

Общий список `issues` описывает проблемы с кадрами и переводами размеченных надписей. В списке языка находятся замечания по озвучке, таймингу, меткам кадров и списку голосов. Каждое замечание содержит код проблемы и, где применимо, путь, язык, `cue` или текст надписи. В интерфейсе список раскрывается в разделе «Паспорт готовности». Проверка сборки отдельно проверяет длительности и файлы.

У задачи есть `id`, `status`, `log`, `outputs` и `exit_code`. Статусы `queued` и `running` означают, что нужно продолжать опрос. `succeeded` означает успешное завершение, а `failed` указывает на ошибку. `exit_code` равен `null` до завершения процесса. Элементы `outputs` содержат относительный путь `path` и локальный URL `url` для загрузки файла. Ошибки запроса возвращаются как `{error: "сообщение"}`. При ответе `409` дождитесь завершения текущей задачи и повторите запуск.

Параметр `command` принимает `build` (по умолчанию) или `scan` для OCR. Для `build` передайте `languages` как массив кодов. Если массив пуст или отсутствует, движок попробует все настроенные языки. Параметр `resolution` принимает `1080p` (по умолчанию) или `360p`. Укажите `youtube: true` для мастера с дополнительными WAV и `dry_run: true` для проверки без записи файлов. Оба флага по умолчанию выключены.

В режиме YouTube в интерфейсе есть список «Основной язык видео». Через API передайте `master_language`, например `"ru"`. Озвучка этого языка определяет монтаж и длительность. По умолчанию берётся `source_language` из проекта. Общие иллюстрации сохраняют исходные надписи. Для сборки с альтернативным мастером файлы сохраняются в `editions/youtube/<разрешение>/masters/<основной язык>/`. В CLI этому соответствует `--master-language ru`.

Пример проверки русского дубля к английскому мастеру в PowerShell.

```powershell
$base = 'http://127.0.0.1:8765'
$body = @{
    path = 'output/seventh-car'
    command = 'build'
    languages = @('ru')
    youtube = $true
    resolution = '360p'
    dry_run = $true
} | ConvertTo-Json
$job = Invoke-RestMethod -Method Post -Uri "$base/api/jobs" -ContentType 'application/json' -Body $body
while ($job.status -in @('queued', 'running')) {
    Start-Sleep -Seconds 1
    $job = Invoke-RestMethod -Uri "$base/api/jobs/$($job.id)"
}
if ($job.status -ne 'succeeded') { throw $job.log }
$job.log
$job.outputs
```

Для записи видео и WAV повторите запрос с `dry_run = $false`. Используйте `url` из ответа для загрузки файла через тот же сервер.

## Сборка из командной строки

Из корня проекта в PowerShell:

```powershell
python series-engine/series.py scan output/seventh-car --dry-run
python series-engine/series.py scan output/seventh-car
python series-engine/series.py frames output/seventh-car
python series-engine/series.py build output/seventh-car --language ru
python series-engine/series.py build output/seventh-car --language ru --resolution 360p
```

Команда `build` без `--language` обработает все языки из `series.json`. Если дорожка или тайминг отсутствуют, движок продолжит остальные версии и перечислит пропуски. `frames` может подготовить иллюстрации до записи голоса. `--dry-run` проверяет входы без записи файлов.

По умолчанию `build` экспортирует `video.mp4` в 1080p (1920 × 1080). Можно явно указать `--resolution 1080p`. Для быстрого теста укажите `--resolution 360p`. Тестовый файл `video-360p.mp4` сохраняется рядом с финальным.

Для одного видео с переключаемыми языками на YouTube используйте `--youtube`. Движок собирает мастер на `source_language` или на языке, выбранном через `--master-language`. Параметр `--language` выбирает дополнительные дорожки. Его можно повторить. Без него движок попробует собрать все языки из конфигурации.

```powershell
python series-engine/series.py build output/seventh-car --youtube --language ru --resolution 360p
```

Мастер и отдельные WAV сохраняются в `editions/youtube/<разрешение>/`. Для примера выше мастер находится в `en/video-360p.mp4`, а русская дорожка в `ru.wav`. Загружайте мастер как видео, а WAV как дополнительную аудиодорожку. `--dry-run` проверяет соответствие блоков и сообщает, для скольких из них изменение темпа превышает 20%.

Во всех языках должны совпадать порядок и ID блоков. Число реплик внутри блока может различаться. В старом тайминге блок определяется полем `id`. В `utterances.json` можно задать общий `id` явно. Без него движок берёт часть `cue` до последнего двоеточия. Движок меняет темп речи по блокам и доводит каждый блок до длины мастера. Если нужен темп вне диапазона 0,5–2×, он укажет блок для редактуры или повторной озвучки.

## Входные файлы

- `series.json` задаёт раскадровку, языки, шрифты и словарь. Пути к файлам языков по умолчанию имеют вид `<язык>/timeline.json` и `<язык>/narration.wav`. Если готовые иллюстрации содержат утверждённые исходные надписи, задайте их язык в `source_language`. Для этой версии движок берёт текст прямо из иллюстраций.
- В общей раскадровке у каждого кадра есть уникальный `cue` и путь `image` к иллюстрации 16:9. Поставьте `"ocr": true` только там, где есть надпись для перевода. Старые раскадровки можно размечать списком `ocr_images` в конфигурации.
- Если известны точный текст и координаты, задайте их в `regions` по имени файла. `box` содержит нормализованные `x, y, ширину, высоту` в пределах 0–1. Для наклонной надписи можно задать `angle` в радианах. Эти кадры обходят OCR. Числа без букв, например `21:20`, сохраняются.
- Тайминг языка хранит тот же `cue` и поля `start`, `end` в секундах. Записи идут подряд от нуля, по 1–9 секунд каждая, и заканчиваются вместе с аудио. Для старых материалов ключ составляется как `id:part`. Если при переводе поменялась разбивка фраз, задайте `cue` явно в разметке озвучки.

Для автоматического тайминга сохраняйте озвучку отдельными PCM WAV на реплику. Положите рядом с ними `<язык>/utterances.json` или задайте путь к списку в `languages.<язык>.utterances` в `series.json`. Записи идут в порядке озвучки. Путь `audio` считается от папки списка, а `cue` указывает на кадр в общей раскадровке. Несколько реплик могут использовать один `cue`.

```json
[
  {"cue": "G01-001:1", "audio": "clips/001.wav"},
  {"cue": "G01-001:2", "audio": "clips/002.wav"}
]
```

`build` измеряет реплики по числу аудиосэмплов, склеивает их и ставит смены кадров на границах реплик. Все WAV одного языка должны иметь одинаковые частоту, разрядность и число каналов. Движок выравнивает границы по 25 кадрам/с и дополняет реплики короче секунды тишиной. Реплики длиннее 9 секунд делите на смысловые части с отдельными WAV и `cue`. Если списка реплик нет, `build` использует прежнюю пару `timeline.json` и `narration.wav`.

## Проверка синхронизации дубляжей

Выберите режим YouTube, основной язык и нужные дубляжи. В разделе «Экспорт» откройте «Синхронизация дубляжей» и нажмите «Рассчитать темп по блокам». Отчёт использует выбранную главу или диапазон, если вы их указали. Для границы внутри блока в таблице показана длительность всего речевого блока, поскольку движок подгоняет блок целиком и затем обрезает его до границы видео.

В API каждый блок содержит `id`, исходное и целевое начало, длительности в секундах, коэффициент `tempo` и `status`. Значение больше 1 ускоряет речь, меньше 1 замедляет. Изменение больше 20% отмечается как заметное. Коэффициент за пределами 0,5–2×, несовпадающие блоки или проблемы с озвучкой требуют исправления перед экспортом. Если `language` не передан, проверяются все языки кроме основного.

Кнопка «Сравнить основные языки» берёт текущий мастер и выбранные дубляжи, затем проверяет каждый язык в роли мастера для той же главы или диапазона. Среди пригодных вариантов сначала учитывается число заметных изменений, затем среднее абсолютное отклонение темпа от 1×. При равенстве приоритет у исходного языка проекта. Мастер меняется по кнопке «Выбрать». Для API повторите `language` для каждого кандидата или опустите этот параметр, чтобы сравнить все языки с готовыми входными файлами.

Нажмите «Сравнить» рядом с речевым блоком, чтобы открыть исходный и подогнанный фрагменты. Подгонка использует тот же фильтр FFmpeg, что и экспорт. Для прослушивания берётся весь речевой блок, даже если диапазон экспорта начинается внутри него. Если темп вне 0,5–2×, доступен исходный фрагмент, а запрос подогнанной версии возвращает 422.

## Вертикальный экспорт

В «Экспорте» выберите формат 9:16. Пресет 1080p даёт 1080×1920, а 360p даёт 360×640. Можно собрать весь проект, главу или диапазон кадров. В API передайте `"aspect":"9:16"`, в CLI используйте `--aspect 9:16`. Вертикальные сборки лежат в отдельной подпапке `vertical/`.

Чтобы сдвинуть вертикальное окно конкретного кадра, в редакторе монтажа включите «Задать центр для вертикального видео» и передвиньте ползунок. Пунктир показывает окно общего плана. В API этой настройке соответствует `rule.vertical_center` от 0 до 1. Без ручной настройки окно ориентируется на выделенный объект или центр изображения. Если объект шире вертикального окна, часть объекта может выйти за его границу.

## Ручной монтаж кадра

В разделе «Экспорт» откройте «Монтаж отдельного кадра», выберите `cue` и настройку. Общий и крупный планы фиксируют крупность на весь кадр. «Резкая склейка» переключает общий план на крупный в указанную секунду от начала кадра. Автоматический режим возвращает обычные склейки. Крупный план приближает изображение на 8%.

Пример тела запроса для `POST /api/project/montage`:

```json
{"path":"output/seventh-car","cue":"G01-001:1","rule":{"mode":"cut","at":2}}
```

Допустимые режимы: `auto`, `wide`, `close`, `cut`. Только `cut` принимает `at` в секундах. Значение округляется до кадра при 25 FPS и должно попадать внутрь кадра в каждой собираемой видеоверсии. Настройки хранятся в `montage.json`. После изменения заново откройте предпросмотр, чтобы увидеть новый монтаж.

Чтобы крупный план сохранял лицо, билет или экран, обведите объект на изображении в редакторе монтажа. Для API добавьте в `rule` поле `"focus":[0.22,0.09,0.52,0.40]`. Это координаты левого верхнего угла, ширина и высота в долях исходного изображения. Движок сдвигает область кадрирования к объекту и при необходимости уменьшает приближение, чтобы область осталась целиком видна. Правило работает и при автоматических склейках. В предпросмотре геометрия крупного плана возвращается в `frames[].crop`.

## Предпросмотр раскадровки

Откройте «Предпросмотр раскадровки с озвучкой», выберите готовый язык и загрузите предпросмотр. Запустите звук через плеер или выберите кадр, чтобы перейти к началу реплики. Браузер переключает исходные иллюстрации по позиции аудио выбранного языка.

Под плеером видна реплика текущего отрезка и идентификатор говорящего. Текст меняется вместе с кадром при воспроизведении и перемотке. Он берётся из записи WAV в манифесте `utterances.json` либо из соответствующей строки готового `timeline.json`. Если одно изображение используется несколько раз, каждый отрезок показывает свою реплику. API `GET /api/project/preview` отдаёт эти данные в `frames[].text` и `frames[].speaker`. Если соответствующее поле в источнике отсутствует, API возвращает `null`.

Движок использует общий WAV языка или соединяет WAV-реплики во временный файл с теми же паузами, что и при сборке. Ссылки на звук действуют в пределах последних восьми открытых предпросмотров и текущего запуска сервера. При истечении ссылки откройте предпросмотр снова.

## Сборка главы или диапазона кадров

В разделе «Экспорт» выберите «Одну главу» или «Диапазон кадров». Обе границы диапазона включаются. Список глав берётся из поля `chapter` раскадровки. Если поля нет, используется префикс `cue` до первого дефиса.

В запросе `POST /api/jobs` передайте `"chapter":"G01"` или пару `"cue_start":"G01-001:2","cue_end":"G01-002:1"`. В CLI используются `--chapter G01` или `--cue-start G01-001:2 --cue-end G01-002:1`. Фрагменты записываются под `editions/fragments/<id>`. В режиме YouTube границы задаёт мастер, а выровненные дубляжи обрезаются до той же длительности. В режиме отдельных видео каждый язык использует собственный тайминг.

## Надписи на кадре

В разделе проекта откройте «Надписи на кадре», выберите кадр по `cue` и обведите текст на исходном изображении. Введите точную исходную надпись и подберите угол в градусах. Если на кадре несколько надписей, разметьте каждую отдельной областью. Выберите язык, проверьте вид надписи в предпросмотре и сохраните разметку. Предпросмотр использует тот же рендерер, что и сборка, и берёт перевод из словаря проекта. Исходный язык сохраняет надпись на картинке.

В ответе `GET /api/project/regions` поле `image` содержит ссылку на исходный кадр, `regions` содержит массив ручных областей или `null`, а `ocr_marked` показывает, отмечен ли кадр для OCR. Пример запроса на проверку разметки без сохранения.

```json
{
  "path": "output/seventh-car",
  "cue": "G01-015:1",
  "regions": [{"text": "UPPER STATION", "box": [0.225, 0.163, 0.53, 0.125], "angle": -0.185}],
  "dry_run": true
}
```

`box` задаёт левый верхний угол, ширину и высоту в долях исходного изображения. Для `angle` API использует радианы. Передайте массив для замены всех ручных областей данного изображения. Пустой массив отключает обработку надписей на этом изображении. `null` удаляет ручную разметку и возвращает OCR для отмеченного кадра. Изменение относится к файлу изображения и действует во всех `cue`, которые на него ссылаются. Чтобы применить изменение, уберите `dry_run` или укажите `false`.

Для `POST /api/project/regions/preview` передайте `path`, `cue`, массив `regions` и код языка в `language`. Запрос вернёт JPEG, а разметка и исходный кадр останутся на диске в прежнем виде.

## Читаемость после кадрирования

Выберите язык озвучки, формат и разрешение. Отчёт проверяет общий и крупный планы по правилам монтажа. Он отмечает области, которые полностью вышли за край, заметно обрезаны или слишком малы в выходных пикселях. Для текста используется высота области от 16 пикселей. Для предметов обе стороны должны быть от 24 пикселей. У наклонной надписи проверяется охватывающий прямоугольник. Это геометрическая проверка, а контраст и читаемость отдельных букв проверяются визуально.

Ручные области надписей из `series.json` включаются автоматически. Важные предметы и дополнительные надписи можно указать по `cue` в `readability.json` рядом с `series.json`. Координаты нормализованы относительно исходного кадра.

```json
{
  "G01-001:1": [{"label": "Компостер", "kind": "object", "box": [0.2, 0.3, 0.2, 0.2]}]
}
```

API возвращает `checked_shots` и `total_shots`. В `issues` доступны `cue`, `start`, `end`, `plan`, `kind`, `label`, `code`, `image_url`, `width_px`, `height_px` и `visible_fraction`. Размеры относятся ко всей области в масштабе выходного кадра, доля видимости относится к части внутри кадра. Кадры без областей не входят в покрытие. Проверяется собственный тайминг выбранного языка. Для общего видео YouTube выберите язык мастера.

## Поиск повторов

Выберите язык и нажмите «Найти повторы». Отчёт отмечает иллюстрации, которые остаются на экране больше 9 секунд подряд, и иллюстрации, которые появляются трижды или чаще за 60 секунд. Соседние отрезки одной картинки объединяются даже при смене крупности. Для каждой часто повторяющейся картинки показывается её самое плотное окно. Если таких окон несколько, отчёт показывает первое.

Движок сравнивает содержимое исходных файлов. Копии под разными именами считаются одной иллюстрацией. Перекодированные или перерисованные варианты считаются отдельными файлами. Для общего видео YouTube выберите язык мастера.

API возвращает `total_shots`, `distinct_images`, пороги в `rules` и список `issues`. Коды `long_hold` и `frequent_return` обозначают долгое удержание и частый возврат. В каждом замечании есть `cue`, `start`, `end`, `image_url` и список `occurrences` с идентификаторами и временем отдельных отрезков или возвратов.

## Субтитры SRT и VTT

В разделе «Субтитры» выберите язык реплик и скачайте отдельный файл. Для своего видео используйте собственный тайминг. Для общего видео YouTube укажите язык мастера. Границы реплик пересчитываются внутри тех же блоков, по которым движок подгоняет озвучку. Изображение и звук остаются в исходных файлах.

Движок берёт текст из записи WAV в `utterances.json` или из готового `timeline.json`. Строки без текста пропускаются. Если в выбранном отрезке текста нет совсем, API возвращает ошибку. Для SRT передайте `format=srt`, для WebVTT передайте `format=vtt`. Через API можно ограничить выгрузку параметром `chapter` или парой `cue_start` и `cue_end`. Границы задаются по мастер-версии, а время в файле начинается с начала выбранного отрезка.

## Сведение звука

В разделе «Сведение звука» включите обработку при экспорте. По желанию укажите относительные пути к музыке и фоновым шумам внутри проекта. Поддерживаются WAV, MP3, FLAC, OGG и M4A. Без фоновых файлов движок выравнивает только голос. Сведение выключено по умолчанию, сборки с обработкой сохраняются отдельно в подкаталоге `mixed`.

Микшер измеряет громкость речи и подбирает усиление к цели −16 LUFS, с ограничением усиления до +24 дБ. Подложки зацикливаются, приглушаются под речью и проходят через общий лимитер. Во фрагменте подложка продолжается с его позиции в полной дорожке. Длительность WAV дубля остаётся равной длительности мастера.

Для `POST /api/jobs` передайте `"mix": true` и, при необходимости, `"music": "audio/music.wav"` и `"ambience": "audio/rain.wav"`. `dry_run` проверяет наличие поддерживаемого аудиопотока и входные тайминги без записи результата. Для CLI доступны `--mix`, `--music` и `--ambience`.

## Звуковая карта локаций

Положите `sound-map.json` рядом с `series.json` и укажите фоновые файлы внутри проекта. В `cues` перечислите отрезки, где должен звучать соответствующий фон.

```json
{
  "locations": {
    "L01": {"name": "Мастерская", "audio": "audio/location/workshop.wav"}
  },
  "cues": {"G01-006:2": "L01"}
}
```

В экспорте откройте «Сведение звука», включите фоны по локациям и просмотрите звуковую карту. На соседних отрезках с одной локацией фон звучит непрерывно. При переходе на другую локацию или неразмеченный отрезок предыдущий фон заканчивается. Музыка и общий фон могут звучать одновременно с фонами локаций. Для YouTube все дорожки используют карту мастера. В отдельных видео используются тайминги своих языков.

Для `POST /api/jobs` укажите `"mix": true, "sound_map": true`. В CLI используйте `--mix --sound-map`. Результаты сохраняются в `mixed/mapped`. API отчёта принимает `chapter` или пару `cue_start` и `cue_end` для просмотра фрагмента. В отчёте время отсчитывается от его начала.

## Главы для YouTube

Выберите мастер для времени и язык названий. Скопируйте полученный список в описание. Отчёт берёт начало каждой главы из первого отрезка этой главы в готовом тайминге озвучки. Старт в тексте округляется вниз до целой секунды. Список начинается с `00:00`. Для готовности нужны минимум три главы длительностью от десяти секунд каждая. [Справка YouTube](https://support.google.com/youtube/answer/9884579)

Файл `chapter-titles.json` рядом с `series.json` задаёт названия по языку. Если названия для главы нет, в списке будет её идентификатор.

```json
{
  "en": {"G01": "The Workshop Ticket"},
  "ru": {"G01": "Билет из мастерской"}
}
```

API возвращает `text`, точные границы `chapters[].start` и `chapters[].end` в секундах, а также `ready` и `issues`. Параметр `master_language` по умолчанию берётся из `source_language`. Для фрагмента укажите `chapter` или пару `cue_start` и `cue_end`. В этом случае отметки считаются от начала фрагмента.

## Пакет публикации

После рендера оставьте выбранные языки, мастера, разрешение и диапазон в разделе экспорта. Откройте «Пакет публикации» и проверьте комплект. При сборке движок создаёт новую папку `publication/<id>` с MP4, WAV, SRT, VTT, главами, обложками, описаниями и `manifest.json`. В режиме YouTube видео одно на все языки, а в режиме отдельных видео MP4 лежит в папке каждого языка. WAV мастера и отдельных видео извлекается из аудио MP4. Готовые WAV дублей копируются.

Добавьте `publication.json` рядом с `series.json`. Общую обложку можно переопределить в настройке языка. Пути к изображениям задаются внутри проекта.

```json
{
  "cover": "frames/cover.jpg",
  "languages": {
    "en": {"description": "The episode description."},
    "ru": {"description": "Описание выпуска."}
  }
}
```

`POST /api/project/package` принимает параметры `POST /api/jobs` для режима `build`. `dry_run: true` проверяет комплект без создания папки. Ответ содержит `ready`, `issues` и, для собранного пакета, `folder` и ссылки `outputs`. Короткий список глав сохраняется отдельным файлом и отмечается предупреждением. Для добавления в описание проверка глав должна пройти. После изменения текста или тайминга пересоберите видео и дубляж перед упаковкой. Проверка сверяет длительность с текущим таймингом, а происхождение уже готового MP4 определяется настройками выбранной сборки.

## Диагностика для агентов

В разделе «Диагностика для агентов» можно проверить все языки или один язык и скопировать JSON. Отчёт проверяет кадры, озвучку, тайминги, ручные склейки и подготовку надписей для локализованной сборки. Для проверки подгонки дублей к конкретному мастеру используется отдельный отчёт синхронизации.

Каждое замечание содержит `code`, `language`, `cue`, `file`, `retry_step`, `message` и `severity`. `file` задаётся относительно рабочего пространства. Если язык, реплика или файл неизвестны либо не применяются, соответствующее поле равно `null`. Для автоматизации используйте `code` и `retry_step`. Например, `missing_wav` с `import_audio` указывает на недостающую реплику, а `missing_ocr` с `scan` указывает на нужный кадр.

`GET /api/jobs/<id>` возвращает такой же список в `issues` после завершения задания. Для сбоя, который движок не смог отнести к конкретному входному файлу или реплике, сохранится общий код и подробности в `log`.

## Очередь сборок

Поставьте первый проект на экспорт, переключитесь на другой и отправьте следующее задание. Раздел «Очередь сборок» показывает задания всех проектов, их статусы и позиции в очереди. Движок выполняет их по одному, в порядке подачи. После ошибки он переходит к следующему заданию.

`POST /api/jobs` возвращает HTTP 202 и идентификатор принятого задания. `GET /api/jobs` возвращает `jobs` с полями `id`, `path`, `command`, `dry_run`, `status`, `exit_code` и `queue_position`. Позиция отсчитывается с единицы для ожидающих заданий. Статусы принимают значения `queued`, `running`, `succeeded`, `failed`. Журнал, диагностику и результаты можно получить через `GET /api/jobs/<id>`.

Сервер хранит очередь и историю в памяти. При штатном завершении он дожидается принятых задач. При принудительной остановке очередь нужно подать заново. Одновременно хранится до 60 записей. Старые завершённые записи освобождают место для новых заданий. При заполнении очереди незавершёнными задачами API возвращает HTTP 429.

## Согласованность кадров

В разделе проекта откройте «Согласованность кадров» и нажмите «Проверить разметку». Отчёт показывает покрытие проверки и кадры, которые стоит пересмотреть. Движок сверяет наблюдения, записанные человеком или агентом после просмотра изображений. Неразмеченные кадры требуют отдельного визуального просмотра.

В `continuity.json` используйте объект с ключами `cue`. Пример записи:

```json
{"G01-014:1":{"place":"L05","expected_place":"L05","shelter":"dry","rain":"inside","outfits":{"timur":"синяя шапка и тёмный свитер"},"reading":{"actor":"timur","can_read":true,"viewer_can_read":true}}}
```

Указывайте только проверенные поля. `shelter` принимает `dry`, `open` или `leaking`, `rain` принимает `inside`, `outside` или `none`. Для намеренной смены одежды укажите ID персонажа в `outfit_changes` на новом кадре. Одежда сравнивается в соседних кадрах с одинаковым `place`. Добавляйте `reading`, когда герой по сценарию должен видеть надпись, и отмечайте видимость для героя и зрителя отдельно. Дождь за окном размечается как `outside`.

Для спорной детали добавьте текстовое поле `review`. Оно появится в отчёте как вопрос для ручной проверки.

## Библиотека локаций и реквизита

Откройте «Локации и реквизит» в разделе проекта. Ищите по названию, описанию или ID, фильтруйте по типу и кадру. Нажмите на подпись референса, чтобы открыть исходное изображение. Путь под референсом можно использовать в задании на новую сцену.

`library.json` хранит список карточек. В каждой карточке нужны уникальный `id`, `kind` со значением `location` или `prop`, `name` и `description`. В `references` укажите объекты с `image` (путь от папки проекта) и `label` (что именно показывает изображение). В `cues` укажите метки кадров, где материал уже использован. API добавляет ссылки `references[].url` и сообщает об отсутствующих изображениях и неизвестных `cue` в `issues`.

## Карточки персонажей

Откройте «Персонажи» в разделе проекта. Выберите `cue`, чтобы увидеть связанных с кадром персонажей, или откройте общий список. В каждой карточке можно раскрыть имена, идентификаторы и подачу голосов по языкам.

Движок объединяет записи `speakers` из языковых `voices.json` по стабильному `voice_id`. В `characters.json` добавьте сведения по тому же ID. Поддерживаются `traits` (характер), `appearance` (внешность), `continuity` (изменения по ходу истории), `portrait` (путь к изображению от папки проекта). Для портретного листа 2×2 можно указать `portrait_grid: [столбец, строка]` с индексами 0 или 1. Если в строке `shots.json` есть `speaker`, карточка говорящего привяжется автоматически. Для безмолвных и других присутствующих в кадре персонажей добавьте в запись кадра `"characters": ["ada", "timur"]`.

## Словарь произношения

В разделе «Версии и языки» откройте «Словарь произношения». Выберите язык, добавьте написание и произносимую форму, проверьте фразу и сохраните словарь. Затем скачайте JSONL для Qwen, OmniVoice или другого синтезатора. Движок сохраняет исходный `narration.jsonl` и все поля реплик, кроме замен в `text` экспортируемой копии.

Для POST передайте `path`, `language`, список `rules` и при необходимости `sample`. Пример правила: `{"term":"Theo","spoken":"Thee-oh","whole_word":true}`. Замены регистронезависимые. Если несколько правил подходят к одной позиции, применяется более длинное. Подстановки выполняются за один проход. Для языков, где слова пишутся без пробелов, можно отключить проверку целого слова для конкретного правила. Словарь хранится в `<язык>/pronunciation.json`. Проверка фразы показывает текст для синтеза. Фактическое произношение зависит от голосовой модели.

## Замена одной реплики

Положите новый PCM WAV внутри проекта. В разделе «Заменить одну реплику» выберите язык, загрузите список, выберите реплику и укажите путь к WAV. «Проверить» показывает новую длительность блока и дорожки. «Заменить реплику» сохраняет изменение. Предпросмотр, отчёт синхронизации и следующая сборка используют обновлённую дорожку.

API принимает `path`, `language`, нумерованный с нуля `index`, путь `audio` от папки проекта и `revision` из списка реплик. `dry_run: true` проверяет результат без сохранения. Устаревший `revision` возвращает 409. Новый файл должен быть совместим по PCM-формату с другими репликами и укладываться в 9 секунд.

Для языка с общим PCM WAV и таймингом первая замена создаёт отдельные клипы остальных реплик и подключает их через `utterances.json`. Исходный общий WAV и тайминг сохраняются. Переход на клипы выполняется один раз.

## Импорт озвучки

Положите список реплик и WAV внутрь проекта. В разделе «Версии и языки» откройте «Импортировать озвучку», выберите язык и укажите путь к списку от папки проекта. Кнопка «Проверить» показывает число реплик и длительность с учётом округления до кадров и пауз. Кнопка «Импортировать» подключает список, оставляя WAV на исходных местах.

```json
{"path":"output/seventh-car","language":"en","manifest":"incoming/en/utterances.json","dry_run":true,"replace":false}
```

Каждая запись указывает существующий в раскадровке `cue` и путь `audio` от папки списка. Все WAV должны иметь один PCM-формат и длительность до 9 секунд. Чтобы применить импорт, опустите `dry_run` или укажите `false`. Для замены существующего списка установите `replace: true`, иначе API вернёт 409. Если для языка раньше использовались `timeline.json` и общий WAV, после импорта движок возьмёт тайминг из списка реплик.

Без готового списка выберите «Папку WAV» и укажите её путь внутри проекта. Можно перетащить папку на поле выбора, чтобы заполнить её имя. В запросе передайте `"folder":"incoming/en"` вместо `manifest`. Назовите WAV по метке кадра, заменив двоеточие на два подчёркивания, например `G01-001__1.wav` для `G01-001:1`. Порядок берётся из раскадровки. Проверка возвращает `issues` с отсутствующими, лишними и неоднозначными файлами. Если в одном кадре несколько реплик или озвучена только часть раскадровки, используйте список JSON.

## Новый проект

В браузере откройте «Создать проект». Укажите название, имя папки латиницей, языки озвучки и язык исходных надписей. Для вызова через API отправьте JSON на `POST /api/projects`.

```json
{"name":"Новая история","slug":"new-story","languages":["en","ru"],"source_language":"en","dry_run":true}
```

План возвращается со статусом 200. Для создания передайте `dry_run: false` или опустите поле. Успешное создание возвращает 201, занятая папка возвращает 409. Мастер создаёт `series.json`, `shots.json`, каталог `frames/` и шаблон `utterances.json` с каталогом `clips/` для каждого языка. Добавьте первый кадр `frames/001.jpg` и первый WAV `<язык>/clips/001.wav`, затем расширяйте раскадровку и списки реплик по общим `cue`.

## Сборка и проверка

Нужны Python, FFmpeg с `drawtext`, FFprobe и английский компонент OCR Windows. Словарь имеет приоритет для имён и сюжетных терминов. Для новых слов доступен параметр `--argos` при установленном пакете и модели перевода. В режиме `glossary_only` движок обрабатывает только известные надписи и игнорирует фоновые находки OCR. Проверьте результаты распознавания в `editions/ocr.json`. Для ошибок OCR можно задать `ocr_aliases` или точную область.

В `editions/<язык>/` сохраняются копии кадров, `frames.json` с указателем на кадр и переводы, а после сборки и `video.mp4`. OCR и обработанные кадры кешируются по содержимому. Плашка ставится поверх найденной области. В кадрах от пяти секунд общий и более близкий планы чередуются монтажными склейками каждые 2–3 секунды. Движок делит длительность кадра на равные планы с точностью до одного видеокадра. Ракурс чтения и перекрытие текста руками проверяются на этапе утверждения общей раскадровки.
